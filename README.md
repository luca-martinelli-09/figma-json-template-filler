# JSON Template Filler

Turn a JSON into ready-made slides, social posts and carousels built from **your own components**. Works in **Figma Design** and **Figma Buzz**.

Scan your templates to get an example JSON, fill it in with your content and generate: one instance per item, every layer filled by name. Perfect for recurring carousels, posts and slide sets.

![JSON Template Filler](assets/cover-1920x1080.png)

## Features

- **Scan templates** – lists every local component and component set, and writes an example JSON with all the fillable layers.
- **Generate** – creates one instance per item and fills text and image layers by name, or by dotted path (`Event1.Title`) when names repeat.
- **Check** – a dry run: shows which layers each item fills, unknown keys (with a "did you mean" suggestion), missing images and invalid dates, without creating anything.
- **Rich text** – `**bold**` and `*italic*` use the matching styles of the font already in your template.
- **Hide layers** – set a field to `null` and the layer disappears; with auto layout the gap closes automatically.
- **Images** – from direct URLs, from files dropped on the plugin (`"foto.png"`), or copied from a layer of the file (`"@asset:Logo"`).
- **Dates** – `{ "date": "2026-12-06T17:00", "format": "EEEE d MMMM" }` writes "domenica 6 dicembre": the weekday is computed for you (it, en, de, fr, es).
- **Variables** – `{{anno}}`, `{{data|EEEE d MMMM|upper}}` anywhere in the JSON, defined once per set.
- **Defaults and inheritance** – `defaults` per template and `extends` between items: write the shared fields once.
- **Update instead of regenerate** – items with the same name are refreshed in place; the JSON stays the source of truth.
- **JSON from selection** – select generated items and get their JSON back, bold/italic included.
- **Export** – PNG, JPG, PDF or SVG of the selection or right after generation, downloaded from the plugin.
- **Overflow check and auto-fit** – fixed-size text boxes that overflow are reported, or shrunk to fit with `"fit": true`.
- **Variants and properties** – pick a variant of a component set and set boolean or text component properties.
- **Color palettes** – swap hex colors or color styles per set or per item (e.g. every `Green - …` style becomes `Blue - …`).
- **Reminders** – add a `note` to an item and it is shown after generation (e.g. which picture still needs to be added).
- **Placement** – in Figma Design each new set lands under the previous one, in a row, a column or one row per template (`layout`); in Figma Buzz each set is a new row of the canvas grid.
- **Editor** – live validation with the line of a JSON error, hints on unknown keys, recent JSONs, drag and drop of `.json` files and images.

## How it works

1. Build your templates as local components (e.g. `Cover`, `Text slide`, `Image slide`, `End`). Give meaningful names to the layers you want to fill (`Title`, `Body`, `Photo`…).
2. Run the plugin and press **Scan templates**: the editor is filled with an example JSON, one item per template.
3. Duplicate, reorder and fill the items with your content, or paste/drop a JSON you prepared elsewhere.
4. Press **Check** to see what would happen (which layers get filled, what is missing), then **Generate** (or Ctrl/⌘ + Enter).
   - **Figma Buzz**: the items are placed in a new row at the bottom of the canvas grid.
   - **Figma Design**: the items are placed in a new auto-layout frame, under the last set generated by the plugin (or to the right of the content the first time).
5. To change something later, edit the JSON, tick **Update existing items with the same name** and generate again: the instances keep their place and are refilled. Select them and press **JSON from selection** to get the JSON back, or **Export selection** for PNG/JPG/PDF/SVG files.

## JSON format

```json
{
  "name": "Episode 39",
  "slides": [
    { "template": "Cover", "fields": { "Title": "Will quantum computers break the Internet?" } },
    { "template": "Text slide", "fields": { "Title": "The lock of the Internet", "Body": "Every time you open **home banking**…" } },
    { "template": "Text slide", "fields": { "Title": null, "Body": "Continuation without a heading." } },
    { "template": "Image slide", "fields": { "Photo": "https://example.com/photo.jpg", "Body": "…" }, "note": "Check the photo credits" },
    { "template": "Card", "variant": { "Size": "Large" }, "props": { "Show badge": false }, "fields": { "Label": "New" } }
  ]
}
```

| Key | Meaning |
|---|---|
| `name` | Optional name of the set: used for the Buzz row, the Design frame and the generated instances. |
| `slides` | Items to create, in order. A bare array (without `name`) works too. |
| `sets` | Several sets in one JSON: `{ "sets": [ { "name": …, "slides": […] }, … ] }`. Each set gets its own Buzz row or Design frame. |
| `template` | Name of a local component or component set. |
| `variant` | For component sets: the variant properties to pick. Otherwise the default variant is used. |
| `props` | Component properties (boolean or text) by name. |
| `fields` | Layer name → value, or dotted layer path → value. See below. |
| `colors` | Color style swaps, on the set (all items) or on a single item (overrides the set). See below. |
| `note` | Reminder shown in the plugin after generation. |
| `gap` | Optional spacing between items in the Figma Design frame (default 80). |
| `layout` | Figma Design: `"row"` (default), `"column"` or `"byTemplate"` (one row per template). In Buzz `"byTemplate"` makes one row per template. |
| `vars` | Variables for `{{name}}` placeholders, on the set or on a single item. See below. |
| `defaults` | Fields, props, colors… applied to every item of a template (`"*"` = every template). See below. |
| `extends` | On an item: copy another item (its number, or its `name`) and override only what changes. |
| `fit` | `true` or a minimum font size: shrink overflowing fixed-size text boxes (set, item or single value). |
| `update` | `true`: refresh the items that already exist with the same name instead of creating new ones (same as the checkbox). |
| `export` | `"PNG"`, `"PDF"`… or `{ "format": "PNG", "scale": 2 }`: download the generated items right away. |

### Field values

| Value | Result |
|---|---|
| `"Some text"` | Replaces the text of a text layer. Supports `**bold**` and `*italic*`; escape a literal asterisk with `\*`. |
| `"https://…/image.jpg"` | Fills a shape or frame with the image (scaled to fill). |
| `null` or `false` | Hides the layer. |
| `"foto.png"` or `"file:foto.png"` | Fills the layer with an image dropped on the plugin (the **Images** strip; drop them on the editor or use **+ add**). Matched by file name, case doesn't matter. |
| `"@asset:Logo banda"` | Copies the image fill of the layer called `Logo banda` found in this file (any page). |
| `"@keep"` | Leaves the layer as it is (what **JSON from selection** writes for images). |
| `["a", "b", null]` | Fills the layers with the same name one by one, in layer order (e.g. the cards of a calendar). `null` hides that one. |
| `{ "visible": false }` | Hides the layer (explicit form). |
| `{ "text": "…", "fit": true }` | Text that is shrunk until it fits a fixed-size box (`"fit": 12` = don't go below 12). `"case": "upper"` / `"title"` / `"lower"` changes the case. |
| `{ "date": "2026-12-06T17:00", "format": "EEEE d MMMM yyyy" }` | A formatted date, see below. |

### Colors

`colors` swaps colors, on the whole set or on a single item:

```json
{
  "name": "Teatro",
  "colors": { "#4a9a5e": "#1e88c9", "#e0e8b8": "#d4e9e8" },
  "slides": [ … ]
}
```

- **Hex colors** (`"#4a9a5e": "#1e88c9"`) replace that solid color in fills, strokes and text, in every editor. A layer linked to a color style is detached from it. **Scan templates** adds the colors of each template to the example JSON (the ones linked to a color style, or all of them if none is): change only the right side.
- **Color style names** (Figma Design only) keep the link to the styles: a family name (`"Green": "Blue"`) swaps every style that starts with it (`Green - 200` → `Blue - 200`, also `Green/200`), an exact name (`"Giallo": "Arancione - 500"`) swaps just that style. In Figma Buzz plugins can't read color styles, so use hex colors there.

Every layer with the given name inside the instance is filled, including layers inside nested instances. Keys starting with `_` are ignored, so you can use them for comments.

### Layer paths

When several layers share a name (e.g. a `Title` in the header and one in each event card), you can fill them with an array, or address one of them with a **dotted path** of ancestor names:

```json
{
  "template": "Calendar",
  "fields": {
    "Title": "Winter concerts",
    "Event1.Title": "Santa Cecilia",
    "Layout.Body.Event2.Title": "Christmas concerts",
    "Event3.Title": null
  }
}
```

- The last segment is the layer name; the segments before it are ancestors that must appear in that order between the instance and the layer. Intermediate layers can be skipped (`Event1.Title` also matches `Layout › Body › Event1 › Card › Title`).
- A plain name still fills every layer with that name; a path fills every layer that matches the path (so an array works with paths too).
- A layer whose name itself contains a dot is matched as-is first; the key is read as a path only if no layer has that exact name.
- **Scan templates** writes shared names as the shortest unique path (`Event1.Title`), so the example JSON is ready to fill.

### Dates

```json
"Data": { "date": "2026-12-06T17:00", "format": "EEEE d MMMM yyyy, 'ore' HH.mm", "locale": "it", "case": "title" }
```

→ `Domenica 6 dicembre 2026, ore 17.00`. The weekday is computed, so it can't be wrong. Dates are written as `yyyy-MM-dd`, `yyyy-MM-ddTHH:mm` or `dd/MM/yyyy HH:mm`.

| Token | Output | Token | Output |
|---|---|---|---|
| `yyyy` / `yy` | 2026 / 26 | `EEEE` / `EEE` | domenica / dom |
| `MMMM` / `MMM` | dicembre / dic | `HH` / `H` | 17 / 17 (no leading zero) |
| `MM` / `M` | 12 / 12 (no leading zero) | `mm` | 00 |
| `dd` / `d` | 06 / 6 | `'text'` | literal text |

Locales: `it` (default), `en`, `de`, `fr`, `es`. The default locale can also be set once with `"vars": { "locale": "en" }`.

### Variables

```json
{
  "name": "Winter",
  "vars": { "anno": "2026", "data1": "2026-12-06T17:00", "luogo": "Sona, Sala del Consiglio" },
  "slides": [
    { "template": "Evento", "fields": { "Title": "Concerts {{anno}}", "Data": "{{data1|EEEE d MMMM|upper}}", "Luogo": "{{luogo}}" } }
  ]
}
```

`{{name}}` is replaced in every string of the item (fields, `name`, `note`, `template`). A date variable can be formatted with `{{name|format}}` and the case changed with `|upper`, `|lower` or `|title`. Variables on an item override those of the set; an unknown variable is left as it is and reported.

### Defaults and inheritance

```json
{
  "name": "Winter",
  "defaults": {
    "*": { "fields": { "Logo": "@asset:Logo banda" } },
    "Evento": { "fields": { "Suptitle": "The Culture Office and the Town Band present" }, "colors": { "#c8352b": "#1f5a3a" } }
  },
  "slides": [
    { "template": "Evento", "name": "Base", "fields": { "Title": "Santa Cecilia", "Body": "…" } },
    { "extends": "Base", "fields": { "Title": "Christmas concert" } },
    { "extends": 1, "variant": { "Format": "16/9" } }
  ]
}
```

Merge order: `defaults["*"]` → `defaults[template]` → the item named in `extends` (by `name` or by its number, counting from 1) → the item itself. `fields`, `props`, `variant`, `colors` and `vars` are merged key by key; `name` and `note` are never inherited. A layer missing for a key that comes only from `defaults` is not reported, so `"*"` can list layers that exist in some templates only.

### Update, export and check

- **Update existing items with the same name** (checkbox, or `"update": true` in the set): for every item the plugin looks for an instance on the current page with the same name (the item's `name`, or `<set> – 01`, `– 02`…), resets its overrides and fills it again, swapping the component if the template changed. Items that don't exist yet are created as usual. Keep the names stable and the JSON becomes the single source of truth.
- **JSON from selection**: select generated items (or their frame) and the editor is filled with their JSON: visible texts (with `**bold**` and `*italic*` reconstructed from the font styles), `null` for hidden layers, `"@keep"` for images.
- **Export selection** (PNG/JPG at 1–4x, PDF, SVG): one file per selected item, named after the item (`Cecilia@2x.png`), downloaded by the browser. `"export": { "format": "PNG", "scale": 2 }` in the JSON does the same right after generation.
- **Check**: nothing is created; for each item you get the number of fields that match the template, unknown keys with a suggestion, fields that send the same value to several layers, images that haven't been dropped, invalid dates and, with the update option, whether the item would be created or updated.

## Tips

- Use unique, descriptive layer names inside each component, or group repeated blocks in named frames (`Event1`, `Event2`…) so that paths like `Event1.Title` stay short: the scan reports names shared by several layers.
- Auto layout in your components lets hidden layers collapse cleanly.
- Image URLs must be publicly reachable direct links to PNG, JPG or GIF files. For local files, drop them on the editor (or paste them, or use **+ add**) and use their file name in the JSON (max 4096 px per side, as for any image in Figma). If the file picker opened by **+ add** misbehaves in your Figma app, drag and drop or paste the images instead.
- Text boxes with a fixed size (not auto-height) are measured after filling: an overflow is reported, or fixed with `"fit": true`.
- The badge above the editor tells you the line of a JSON error: click it to jump there. Recent JSONs are kept in the **Recent…** menu (stored locally by Figma, up to 8).
- Fonts must be available to Figma. If a bold or italic style doesn't exist for a font, the text stays regular and you get a warning.

## Limitations

- Only **local** components are used as templates (not components from a library).
- Figma Design and Figma Buzz are supported; FigJam and Figma Slides are not.

## Privacy

The plugin only reads and edits the current file and does not collect or send any data. Recent JSONs are stored locally by Figma (plugin client storage) and can be cleared from the **Recent…** menu. Network requests:

- the image URLs you put in the JSON, to fill image layers (images dropped on the plugin stay in Figma);
- Google Fonts, to load the Inter font used by the plugin interface.

## Development

The plugin is written in TypeScript (`code.ts`) and compiled to `code.js`; the interface is `ui.html`.

```bash
npm install
npm run build   # or: npm run watch
```

Then in the Figma desktop app: Plugins → Development → Import plugin from manifest… and pick `manifest.json`.
